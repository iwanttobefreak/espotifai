Instancias

Cada casa, su propia puerta.

Espotifai no guarda tu música en la nube. El frontal es la portada del proyecto; tu música vive en tu instancia, en tu casa.

1Elige tu nombre

Crea un CNAME de tu subdominio a tu DDNS (o a la IP de tu casa). Si tu IP es dinámica, apunta al DDNS.

micasa.espotifai.es.  CNAME  tu-ddns.example.com.

Ejemplo: micasa.espotifai.es → tu-ddns.example.com.

2Despliega y emite TLS

Clona el repo, configura el dominio y el token, y levanta el compose con nginx.

git clone https://github.com/iwanttobefreak/espotifai.git
cd espotifai/examples/con-nginx
cp .env.example .env
nano .env
nano nginx.conf   # micasa.espotifai.es
docker compose up -d --build

Después, emite el certificado con certbot (el README lo detalla).

Qué es cada cosa: espotifai.es es el frontal (proyecto, documentación y git). micasa.espotifai.es es tu instancia (app web y API). El frontal no proxya tu música.

Funciones

Lo justo para escuchar bien.

Sin redes sociales, sin recomendaciones y sin funciones que no usas.

Streaming con seek

Servido con Range: puedes moverte por la canción sin descargarla entera.

Cola y listas

Añade a la cola, reproduce a continuación y crea varias listas con tus canciones.

Offline de verdad

Descarga canciones o álbumes al teléfono y escúchalos sin red, desde el fichero local.

Multiusuario

Un token por persona o dispositivo. El admin crea, cambia y revoca sin tocar el resto.

Índice persistente

El escaneo se guarda en data/index.json: arranca rápido y reescanea cuando quieras.

Sin telemetría

No hay analítica ni servicios externos. El único envío opcional es el log de fallos.

App web

La misma biblioteca en el navegador, sin instalar nada: búsqueda, cola y listas.

ZIP por álbum

Descarga el álbum entero en un ZIP generado por el servidor. En la web no hay caché offline.

Despliegue

Docker, con o sin nginx.

Dos ejemplos listos para copiar. El token y la carpeta de música van en .env; nada sensible en el repo. El frontal es estático: esto despliega una instancia.

Sin nginxLo más simple

Servidor directo en el puerto 8088. Ideal para la LAN; la app web no va incluida (solo la API).

# clona y configura
git clone https://github.com/iwanttobefreak/espotifai.git
cd espotifai/examples/sin-nginx
cp .env.example .env
nano .env   # API_TOKEN y MUSIC_DIR

# arranca
docker compose up -d --build

# comprueba
curl http://localhost:8088/api/health
Ver en el repositorio ↗
Con nginxHTTPS + app web + API

nginx termina TLS, sirve la app web en / y proxya la API en /api/. Certbot renueva solo.

# configura el dominio en nginx.conf
cd espotifai/examples/con-nginx
cp .env.example .env
nano .env
nano nginx.conf   # micasa.espotifai.es

docker compose up -d --build

# certificado (una vez)
docker compose run --rm --entrypoint certbot certbot \
  certonly --webroot -w /var/www/certbot \
  -d micasa.espotifai.es --email tu@email.com \
  --agree-tos --no-eff-email
Ver compose + nginx en el repo ↗
Consejo: en producción cambia API_TOKEN antes de arrancar y usa HTTPS fuera de la LAN. Si ya tienes un proxy central, no publiques los puertos 80/443: apunta a espotifai:8088. El CNAME debe existir antes de pedir el certificado.
API

Una API pequeña y predecible.

Cada instancia tiene su propia API. JSON para la biblioteca, audio con rangos, tokens y ZIP de álbumes.

MétodoRutaQué hace
GET/api/healthEstado y nº de pistas
GET/api/libraryArtistas → álbumes → pistas
POST/api/rescanReindexa la carpeta
GET/api/stream/:idAudio con Range
GET/api/cover/:idCarátula del álbum
GET/api/album/:id/zipDescarga el álbum en ZIP
GET/api/usersUsuarios (solo admin)
POST/api/usersCrea usuario + token
 
# biblioteca
curl -H "Authorization: Bearer $TOKEN" \
  https://micasa.espotifai.es/api/library

# stream con seek
curl -H "Authorization: Bearer $TOKEN" \
  -H "Range: bytes=0-1023" \
  https://micasa.espotifai.es/api/stream/<id>

# crear un token para el salón
curl -X POST -H "Authorization: Bearer $ADMIN" \
  -H "Content-Type: application/json" \
  -d '{"name":"salon"}' \
  https://micasa.espotifai.es/api/users
